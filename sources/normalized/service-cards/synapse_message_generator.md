## INFRASTRUCTURE CLASSIFICATION

1. **Request-driven or proactive?**  
   Request-driven through authenticated HTTP endpoints. No proactive message-generation trigger is defined.

2. **Stateless or stateful?**  
   The API contracts are stateless-looking: each request supplies the business, customer or occasion, channel, offer, and length constraints. Server-side history or persistence is not described.

3. **Synchronous or asynchronous?**  
   Synchronous request/response. No job or polling contract is defined.

4. **Online or batch-oriented?**  
   Online, one generation request at a time. No bulk-generation endpoint is defined.

5. **Raw data or derived data?**  
   Consumes caller-supplied identifiers, campaign parameters, offer rules, and message constraints. Any customer/business datasets fetched internally are absent from the Swagger.

# 1. PURPOSE

- Generate Persian marketing messages using an LLM.
- Churn operation:
  - generate a churn-prevention message for a customer.
- Occasional-campaign operation:
  - generate a message for a named occasion and campaign style.
- Return the generated text and token-usage cost.
- The intended consumer is the platform or campaign system requesting message content.

# 2. TRIGGER / EXECUTION MODE

- **Mode:** authenticated HTTP API.
- **Execution:** synchronous request/response.
- **Authentication:** API key in the `authorization` header.
- **Can initiate work proactively?** No proactive execution is defined.

Endpoints:

- `POST /dev/v1/agent/churn`
- `POST /dev/v1/agent/occasional-campaign`
