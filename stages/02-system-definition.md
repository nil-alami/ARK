# Stage 02 — System definition

Governing source: `system-design-prompt.md` section **1. System definition**.

Inputs: approved Stage 01 and ARK assumptions.

## Work

- Define business goals, users, consuming systems, boundary, inside/outside responsibilities, use cases, out-of-scope items, success criteria, requirements, constraints, and assumptions.
- Create stable requirement IDs (`ARK-FR-*`, `ARK-NFR-*`, `ARK-CON-*`).
- Start the requirements traceability matrix using `templates/requirements-traceability.md`.
- Do not choose an architecture style yet.

Output: `outputs/stages/02-system-definition.md`.

Gate: every requirement is testable or explicitly marked provisional; boundaries and out-of-scope items are unambiguous; unknown scale/SLO values remain unknown.
